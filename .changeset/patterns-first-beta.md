"@allons-y/webc-patterns": minor
---

First beta: generic WebC components and page layouts for Eleventy sites, and the Norn plugin that registers them. Each component carries its own CSS, so a page ships only the styles of the components it uses. Part of Norn: every component is a `norn-*` tag, and the hidden globals carry the same prefix so they don't collide with a project's own. Every layer nests under `@layer norn`, and the registered helpers are `nornAdjacent`, `nornHeadings`, `nornComponentStrings`, `nornHook`, `nornIcons`, and, with the code sample, `nornTokenRanges`.

The Norn plugin, `@allons-y/webc-patterns/plugin`, is the one setup call: `config.addPlugin(norn, { props })`. It owns the project's single `@11ty/eleventy-plugin-webc` registration (more globs go in `components`, and a second registration fails the build), registers the helpers, the Markdown add-ons, and `dropEmptyBundleTags`, and adds `props`, a mapping from the project's own page data to the layout props, as `eleventyComputed.norn`. Without a mapping, the layouts read the same-named page data, and every list prop defaults to `[]`. Options: `props`, `layouts`, `components`, `exclude`, `strings`, `icons`, `markdown`, and `defaults`. `fillHooks(config, { head, banner, cta, credit })` adds markup to the page frame's four hooks, for a theme or the project. `@allons-y/webc-code-sample` is an optional peer: installed, the plugin registers it and the layouts show code with it; without it, they show `<pre><code>`.

- Layouts, shipped as files in `layouts/` and registered under the project's layouts folder: `norn-base` (the head, skip link, header, `main`, and footer, filled from props, with `lang` and `dir` on `<html>` (`dir` is a prop, else `rtl` for a right-to-left `lang`), the Open Graph and `twitter:card` tags and an optional `ogImage` share image resolved against `url`; a relative image with no absolute `url` logs a `norn-head:` warning, leaves out the image tags, and sets the card to `summary`; a Markdown page on `norn-base` has its call-outs, code fences, and tables compiled), `norn-docs`, `norn-docs-home`, `norn-landing`, `norn-workspaces`, and `norn-workspace`, each extending `norn-base`. A project file named like a shipped layout fails the build; `layouts: ["norn-landing"]` leaves one out for the project to supply.
- Stylesheets: `css/base.css` and `css/print.css`, embedded in `norn-base`, and an optional `css/reset.css`, exported from the plugin as `reset`, `base`, and `print`. The components and layouts look the same without the reset. `norn-head` declares the layer order inline, ahead of the bundle links.
- Project data builders, `@allons-y/webc-patterns/project`: `buildSite` (with a `host` option for the URL), `buildWorkspaces`, `npmRelease`, and `accentHex`, with the `project.json` schema at `@allons-y/webc-patterns/schema/project.schema.json`.
- Project icons: the plugin's `icons` option takes a glob or list of globs of `.svg` files, each named for its file without the extension, or a record of names to a path or `{ src, mirror }`. The plugin reads the files at build time and registers them through the `nornIcons` helper. `norn-svg-icon` draws a project icon beside its built-in set, over a built-in of the same name. The icon keeps its own paint and takes its `viewBox` from the file, else from a numeric `width` and `height`, else `0 0 24 24`. Its size, title, scripts, and event handlers are dropped, and `mirror: true` flips it in right-to-left text. An unknown name fails the build and lists the built-in and the project names. Without the plugin, `norn-svg-icon` draws the built-in set only.

The shared design tokens are `--norn-*` custom properties named for their path in `tokens.json`: `--norn-ui-accent`, `--norn-surface-base`, `--norn-text-muted`, `--norn-font-body`, `--norn-code-keyword`, `--norn-space-m`. Each component reads a token with its default compiled in as the fallback, so nothing has to define them, and a project sets any of them in its own `tokens.css` to restyle every component. A theme is a file of such properties. The base styles define no token.

- Document and page frame: `norn-head`, `norn-skip-link`, `norn-header`, `norn-footer`, `norn-sidebar-layout`, `norn-hero`, `norn-section`, `norn-rich-text`, and `norn-pager`.
- Navigation: `norn-side-nav`, `norn-breadcrumb-nav`, `norn-toc`, `norn-heading-anchor`, and `norn-search` (live Pagefind results, or a web search of the site without an index).
- Content: `norn-content-card`, `norn-card-grid`, `norn-data-table`, `norn-call-out`, `norn-notice`, `norn-accordion-group`, `norn-code-tabs`, `norn-tag-list`, `norn-link-button`, and `norn-svg-icon`.
- Controls: `norn-segmented-control`, `norn-theme-toggle`, and `norn-copy-button`.
- Helpers: `patterns()` for the components glob, `componentStrings` and `defaultStrings` for site-wide strings, `adjacent`, and `dropEmptyBundleTags`. The Markdown add-on is `@allons-y/webc-patterns/markdown`: the markdown-it amends `callouts`, `headingAnchors`, and `scrollTables`, plus `headings` and `slugify`. It writes the markup an author would write by hand and no text of its own.

Content goes in slots and settings in props. Every string a visitor sees or hears is content in the page, in a named slot whose fallback is the site's `componentStrings` (by language too, through `page.lang`), then English. A layout's own texts, such as "Get started" and "License: {license}", are keys under the layout's name in the same registry. Accessible names point `aria-labelledby` at that text, and text only a script shows sits in the page, hidden, for the script to read. Counts follow the plural rules of the page's language. Every component meets WCAG 2.2 AA in light, dark, and forced colors.
