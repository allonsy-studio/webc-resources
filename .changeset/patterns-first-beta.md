"@allons-y/webc-patterns": minor

First beta: generic WebC components and page layouts for Eleventy sites, and the Norn plugin that registers them. Each component carries its own CSS, so a page ships only the styles of the components it uses. Part of Norn: every component is a `norn-*` tag, and the hidden globals carry the same prefix so they don't collide with a project's own. Every layer nests under `@layer norn`, and the registered helpers are `nornAdjacent`, `nornHeadings`, `nornComponentStrings`, `nornHook`, `nornIcons`, `nornCompiles`, and, with the code sample, `nornTokenRanges`.

The Norn plugin, `@allons-y/webc-patterns/plugin`, is the one setup call: `config.addPlugin(norn, { props })`. It owns the project's single `@11ty/eleventy-plugin-webc` registration (more globs go in `components`, and a second registration fails the build), registers the helpers, the Markdown add-ons, and `dropEmptyBundleTags`, and adds `props`, a mapping from the project's own page data to the layout props, as `eleventyComputed.norn`. Without a mapping, the layouts read the same-named page data, and every list prop defaults to `[]`. `norn` is a reserved data key: a page that sets it fails the build. Options: `props`, `layouts`, `components`, `exclude`, `strings`, `icons`, `markdown`, and `defaults`. `fillHooks(config, { head, banner, cta, credit })` adds markup to the page frame's four hooks, for a theme or the project. `@allons-y/webc-code-sample` is an optional peer: installed, the plugin registers it and the layouts show code with it; without it, the plugin registers a plain `norn-code-block` that shows every sample, hand-written or a layout's, as `<pre><code>` with its `id` and caption.

- Layouts, shipped as files in `layouts/` and registered under the project's layouts folder: `norn-base` (the head, skip link, header, `main`, and footer, filled from props, with `lang` and `dir` on `<html>` (`dir` is a prop, else `rtl` for a right-to-left `lang`), the Open Graph and `twitter:card` tags and an optional `ogImage` share image resolved against `url`; a relative image with no absolute `url` logs a `norn-head:` warning, leaves out the image tags, and sets the card to `summary`; Markdown content has its callouts, code fences, and tables compiled exactly once on every layout, also through a project's Nunjucks or Liquid layout or a layout alias, and content WebC already compiled goes in as it is), `norn-docs`, `norn-docs-home`, `norn-landing`, `norn-workspaces-home`, and `norn-workspace`, each extending `norn-base`. Every layout renders the page body, the three home layouts after their own sections. A project file named like a shipped layout fails the build; `layouts: ["norn-landing"]` leaves one out for the project to supply.
- Stylesheets: `css/base.css` and `css/print.css`, embedded in `norn-base`, and an optional `css/reset.css`, exported from the plugin as `reset`, `base`, and `print`. The components and layouts look the same without the reset. `norn-head` declares the layer order inline, ahead of the bundle links.
- Project data builders, `@allons-y/webc-patterns/project`: `buildSite` (with a `host` option for the URL), `buildWorkspaces` (each README rendered with the site's Markdown add-ons, its raw HTML as HTML), `npmRelease`, and `accentHex`, with the `project.json` schema at `@allons-y/webc-patterns/schema/project.schema.json`.
- Project icons: the plugin's `icons` option takes a glob or list of globs of `.svg` files, each named for its file without the extension, or a record of names to a path or `{ src, mirror }`. The plugin reads the files at build time and registers them through the `nornIcons` helper. `norn-icon` draws a project icon beside its built-in set, over a built-in of the same name. The icon keeps its own paint and takes its `viewBox` from the file, else from a numeric `width` and `height`, else `0 0 24 24`. Its size, title, scripts, and event handlers are dropped, its ids and the references to them are prefixed with the icon's name so two icons cannot clip or fill each other, and `mirror: true` flips it in right-to-left text. An unknown name fails the build and lists the built-in and the project names. Without the plugin, `norn-icon` draws the built-in set only.

The shared design tokens are `--norn-*` custom properties named for their path in `tokens.json`: `--norn-ui-accent`, `--norn-ui-border-strong`, `--norn-ui-focus-width`, `--norn-ui-state-hover`, `--norn-status-info`, `--norn-surface-base`, `--norn-text-muted`, `--norn-font-body`, `--norn-font-size-m`, `--norn-code-keyword`, `--norn-space-m`, `--norn-layout-width`. Each component reads a token with its default compiled in as the fallback, so nothing has to define them, and a project sets any of them in its own `tokens.css` to restyle every component. A theme is a file of such properties. The base styles define no token.

- Document and page frame: `norn-head`, `norn-skip-link`, `norn-header`, `norn-footer`, `norn-sidebar-layout`, `norn-hero`, `norn-rich-text`, and `norn-pager`.
- Navigation: `norn-side-nav`, `norn-breadcrumbs`, `norn-toc`, `norn-heading-anchor`, and `norn-search` (live Pagefind results, or a web search of the site without an index).
- Content: `norn-card`, `norn-card-grid`, `norn-simple-table`, `norn-callout`, `norn-notice`, `norn-accordion`, `norn-code-tabs`, `norn-fact-list`, `norn-link-button`, and `norn-icon`.
- Controls: `norn-segmented-control`, `norn-theme-toggle`, and `norn-copy-button`.
- Helpers: `patterns()` for the components glob, `componentStrings` and `defaultStrings` for site-wide strings, `adjacent`, and `dropEmptyBundleTags`. The Markdown add-on is `@allons-y/webc-patterns/markdown`: the markdown-it amends `webcTags` (a component tag with `@` props stays a tag in Markdown, in a `.md` page and in a `webc:type="11ty"` block, and an embed `<script>` or `<link>` reaches the browser as written), `callouts`, `singleTitle` (a docs page keeps one h1: a leading `# Title` that repeats the title goes, and any other h1 becomes an h2), `headingAnchors`, and `scrollTables`, plus `headings` and `slugify`. Markdown headings render as `norn-heading-anchor`, and `headings` lists hand-written ones too. Heading ids keep the letters and digits of any script, and stay unique across a page, two Markdown blocks included. It writes the markup an author would write by hand and no text of its own.

The look is light: one 2px focus ring everywhere, one hover and press layer on every control (and a tint for the selected or current item), borders only where they carry meaning (a control's edge at 3:1, a hairline between rows), one container signal (a fill, or a tint with a 3px bar for a status), two radii, five type steps, one control height (2.25rem, 2.75rem for a coarse pointer), and flat surfaces, with a shadow only for the search results. In forced colors a selected, current, or focused item uses a system color, and a filled button stays filled. `norn-segmented-control` tints its checked option with no sliding thumb; `norn-link-button` has `primary`, `secondary` (a 1px outline), and `quiet` (text only) variants; `norn-copy-button` keeps its width, swaps to a check in the success color, and can be `compact`; `norn-card` is a fill with a heading link that covers the card, and its `accent` prop draws a 2px line along its top in the accent or a status color; `norn-card-grid` has no accent cycle; `norn-notice` is a status tint with a 3px bar, and `norn-callout` is an editorial aside, a raised panel with an eyebrow label and the body set like a pull quote; a heading anchor's `#` hangs in the margin and shows on hover and focus from 70rem, and stays in line below it, with one recipe in `norn-heading-anchor`, so `--norn-heading-anchor-mark` colors it inside `norn-rich-text` too; `norn-simple-table` keeps its columns readable, scrolls, and shades the edge that has more; `norn-header` folds its links into a closed `<details>` below 40rem, named by its `summary` slot or the `norn-header` string; `norn-sidebar-layout` folds its navigation into a closed `<details>` below 37.5rem, named by its `summary` slot or the `norn-sidebar-layout` string; and `norn-docs` puts its contents in a sticky column from 60rem and folds them under their title below it. The `@supports not at-rule(@scope)` copy of `norn-rich-text`'s prose styles is written by the build.

Content goes in slots and settings in props. Every string a visitor sees or hears is content in the page, in a named slot whose fallback is the site's `componentStrings` (by language too, through `page.lang`), then English. A layout's own texts, such as "Get started" and "License: {license}", are keys under the layout's name in the same registry. Accessible names point `aria-labelledby` at that text, and text only a script shows sits in the page, hidden, for the script to read. Counts follow the plural rules of the page's language. Every component meets WCAG 2.2 AA in light, dark, and forced colors.
